## 二、技术方案决策："电脑不运行也能推送"（重点）

### 2.1 现状盘点

- 现有 4 条本机 Hermes Cron 推飞书（早7/午12/晚19/日终22）+ 1 条题库更新 Cron（每2天8:00）——**全部依赖本机运行**。
- 旧系统已有云端模板：`~/hermes-study-mentor/.github/workflows/daily-intel.yml`，内置北京时间 7:00/12:00/19:00 三个定时 + `workflow_dispatch` 手动触发，job 执行 `push_intel.py` 并注入 `FEISHU_APP_ID / FEISHU_APP_SECRET / FEISHU_CHAT_ID` 三个 secrets。
- **缺口**：① 项目未推送到 GitHub 仓库；② 三个 secrets 未配置；③ `push_intel.py` 目前是"本机版"（读取本机 `.env` 文件路径、消息内嵌 `localhost:8899` 链接），**云端无此文件，必须改造为读环境变量**。
- 飞书凭据齐备：`APP_ID=cli_aaf1e0c7c6f8dbe5`，聊天ID `oc_881b2febb4c96903394bc9e85cce3bf0`，SECRET 存于本机 `.env`（`~/AppData/Local/hermes/profiles/learning-system/.env`，含 FEISHU 配置 6 处）。

### 2.2 方案对比

| 维度 | **方案A：GitHub Actions（推荐）** | 方案B：本机 Hermes Cron（现状） | 方案C：云服务器/PythonAnywhere |
|------|------|------|------|
| 电脑不运行能否推送 | ✅ 能（云端执行） | ❌ 不能（关机/休眠即漏推） | ✅ 能 |
| 成本 | 免费（2000分钟/月，每日3次≈90分钟/月，充裕） | 免费 | 付费或免费额度有限 |
| 定时可靠性 | 高（可能有 5–15 分钟延迟） | 高（但依赖机器在线） | 高 |
| 密钥安全 | GitHub Secrets 加密存储 | 本机 .env | 需自管 |
| 实时性 | 分钟级延迟（定时任务非精确） | 秒级（可高频） | 分钟级 |
| 落地成本 | 模板已有，补仓库+secrets+脚本改造即可 | 已在使用 | 需新部署，成本高 |

**结论：方案A（GitHub Actions）为主方案，满足"电脑不运行也能推送"核心诉求；方案B（本机 Cron）保留为补充通道**，承担"实时盯着"的高频突发情报（如考试公告当天下发），云端负责每日 3 次汇总推送。两者按内容类型分工，避免重复打扰。

### 2.3 落地步骤（TA-001 执行）

1. **安全先行**：项目根新建 `.gitignore`（排除 `.env`、`data/progress/`、`data/mastery/`、`__pycache__/`、`.kb-tmp/`、`*.bak`）。
2. **推送到 GitHub**：`git init` → 创建**私有仓库**（避免 secrets 相关风险）→ 推送全量代码（含题库、知识卡、脚本、workflow 模板）。
3. **配置 secrets**：仓库 Settings→Secrets and variables→Actions，新增 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_CHAT_ID`（取值自本机 `.env`，注意 SECRET 需人工复制，不得入库）。
4. **脚本云端化改造**：`push_intel.py` 改为 `os.environ.get()` 读取三密钥（不再依赖本机 `.env` 路径）；情报内容改为云端可抓取的公开源（河南省人事考试网、新华网/人民网时政频道等，用 `requests/feedparser`）；移除 `localhost:8899` 链接或改为提示文案。
5. **验证**：在 GitHub 仓库手动触发 `workflow_dispatch` → 观察 Actions 运行日志 → 确认飞书群收到消息 → 记录消息截图/消息ID作为验收凭证。
6. **保留本机 Cron**：作为实时突发情报补充通道，与云端每日汇总分工。

### 2.4 风险与预案

- Actions 定时有分钟级延迟 → 可接受（每日汇总非秒级需求）；若遇 GitHub 不可达，本机 Cron 兜底。
- secrets 泄漏风险 → 使用私有仓库 + `.gitignore` 双保险。
- 免费额度耗尽 → 3次/日×31天≈93分钟/月，远低于 2000 分钟上限，无风险。
