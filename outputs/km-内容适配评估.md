## 二、逐候选项目评估（含 11 个达标候选）

> 评分口径：10 分制，**内容适配综合分** = 五段式×0.2 + 知识卡×0.2 + 错题×0.15 + 掌握度×0.15 + 每日计划×0.1 + 迁移×0.1 + 质量空间×0.1。评分依据 = TA-001 报告功能核实 + 本人对内容模型的专业判断。

### 2.1 面试鸭 liyupi/mianshiya（5,728★，MIT）—— 深入评估 ⭐

**内容模型是否支持五段式解析五字段**：◐ 中。题目对象有"解析"字段（折叠解析），是**单一解析文本**，与我们现状（explanation 单字段内嵌五段）同构——即"迁移不失真，但结构不升级"。要真正落地五字段，需二开：题目表加 4 个字段（term_breakdown/option_analysis/exam_hint/mnemonic）或前端按【】分节渲染。**好消息**：它的"解析字段+选项结构"与我们 `options: {A,B,C,D}` 字典结构天然对齐，五段式升级改造有明确落点。

**知识卡如何映射**：○ 低。面试鸭没有"卡片/页面"概念，知识内容靠"题目+标签+收藏"承载。11 张 Markdown 知识卡（含表格、口诀、例题）**无处安放**——要么塞进题目解析（破坏卡片阅读体验），要么二开独立"知识库/文章"模块（工作量大）。10 维度审核标准（字数/表格/口诀/例题/分值关联）在它上面**无原生挂钩**，只能靠人工维护。

**错题与掌握度数据如何落地**：错题 ◐（有收藏+重复练习，独立错题本需二开）；掌握度 ○ 低（仅粗粒度"分析报告"，无模块级 mastery 模型，且其分析维度是题量/热度而非知识掌握）。我们的 `mastery.json`（12模块×0-100）需自建数据表 + 定时聚合，或外接 py-fsrs。

**内容批量导入难度**：◐ 中。管理端有题目管理，但无公开的批量导入 API/格式文档（TA-001 未核实到），需写脚本直插其数据库（微信云开发 or Express+DB）。15 题 JSON→其题目表映射成本低（字段同构），但 11 张知识卡无对应表，需自建内容表。未来千题级扩展：可行，但受其 schema 约束。

**迁移成本（12模块+15题）**：中。题目**低**，知识卡**高**（无落点）、掌握度/错题**高**（自建）。

**内容质量提升空间**：◐ 中。MIT 许可可自由改造，五字段 schema 可加；但**内容治理功能（审核流、版本、质量评分）为零**，需全部自建。其内容为技术面试题，公基题库全量替换，等于"借壳"。

**内容适配综合分：5.5/10**（五段式 6.5、知识卡 3、错题 4.5、掌握度 3、每日计划 3、迁移 5.5、质量空间 6）

**KM-001 评语**：它是"刷题交互体验"最好的，但对**内容资产**是"借壳"关系——题目能进去，知识卡进不去，掌握度要另起炉灶。内容生产链路上它帮不上忙，反而因为 schema 待二开增加一层维护负担。

### 2.2 学之思 mindskip/xzs（3,891★+3,593★，AGPL-3.0）—— 深入评估

**内容模型是否支持五段式解析五字段**：○ 低。TA-001 核实 README 未见解析字段；作为考试系统其题目对象为固定字段（题干/选项/答案/解析），解析是**单文本兜底**。五段式要么塞进"解析"文本字段（退化回现状、且丢失结构化），要么改 Java 实体类 + 迁移脚本（AGPL 下自用无碍，但 Java 重栈改造成本高）。

**知识卡如何映射**：○ 低。学科+题库管理，无知识卡模块。11 张 Markdown 卡需二开"学习资料"模块或塞入"教材"型题目——**结构保真度最低的候选之一**。

**错题与掌握度数据如何落地**：错题 ● 高——**原生错题本（答错自动收录）是全部候选中机制最完整的**，直接对标我们的 `wrong-questions/` 自动收录逻辑，且带重练闭环。掌握度 ○ 低——成绩/统计粗粒度，无模块级 mastery 模型，需二开或外接。

**内容批量导入难度**：◐ 中。有管理端题目管理（Gitee 社区生态有导入工具链，但未核实）；JSON→其表结构映射中等成本。知识卡无落点。

**迁移成本**：中高。题目中、知识卡高、掌握度高。

**内容质量提升空间**：◐ 中。错题本机制可借鉴为**质量反馈闭环**（错题率高的题目自动进入 KM-001 复核队列——这个思路有价值）；但 AGPL 许可 + Java 栈 + GitHub 社区缺失，长期内容维护生态弱。

**内容适配综合分：4.5/10**（五段式 3.5、知识卡 2、错题 8.5、掌握度 3.5、每日计划 5.5、迁移 4.5、质量空间 5）

**KM-001 评语**：**"考试系统"思维与"学习内容资产"思维错位**。它的错题本是金标准，但知识卡无落点、解析无结构、掌握度无模型——三块核心内容资产都要二开。只适合作为"错题本机制"的参考蓝本，不宜作底座。

### 2.3 Anki（ankitects/anki, 29,680★, AGPL-3.0）+ py-fsrs（468★, MIT）—— 深入评估 ⭐

**内容模型是否支持五段式解析五字段**：◐ 中。Anki 卡片 = 正面/背面 + **任意多个自定义字段 + 模板**（`{{field}}` 渲染），**五字段（correct_answer/term_breakdown/option_analysis/exam_hint/mnemonic）可声明为五个卡片字段**，模板渲染五段式解析——结构保真度是三个深入候选中**最高**的，且不破坏"正面题干→背面解析"的复习流。py-fsrs 提供调度算法，与内容模型解耦。

**知识卡如何映射**：● 高。**卡片即知识卡**，天然契合"知识卡+中国风模板"（TA-001 亦认可）。11 张 Markdown 知识卡 → 按考点粒度拆分为 N 张卡片（如"时政热点"卡拆出"五个必须""九项任务排序"等复习卡），表格/口诀/例题可进模板或字段。10 维度审核标准的"口诀/例题"字段可直接落为卡片字段——**内容质量标准第一次有了原生挂载点**。

**错题与掌握度数据如何落地**：掌握度 ● 高——**FSRS 记忆稳定性/难度模型是业界金标准**，天然覆盖 0-100 掌握度、趋势、薄弱识别，与我们的 mastery.json 语义同构（可映射：retention→mastery，difficulty→weak 标记），且**py-fsrs 为纯 Python 库，pip 即可嵌入 Flask 直接读算**。错题 ◐ 中——Anki 无"错题本"概念，用"重学/搁置/标记"近似，答错自动进重学队列（≈错题收录），但无按题统计的 wrong_count 表，需自建或接受近似。

**内容批量导入难度**：● 高适配。标准导入格式（CSV/TSV/JSON via `genanki` 库），**15 题 → 15 张卡片（题干正面/五字段解析背面）脚本一次转换**；11 张知识卡 → 考点卡片拆分需 KM 人工切分（一次性成本，但切分本身就是质量提升）。未来千题级：genanki 批量生成无压力。

**迁移成本**：低-中。题目低（脚本转换）、知识卡中（需拆分，但拆完即达质量门槛）、掌握度中（FSRS 从 0 起步，历史 mastery.json 可作初始参数注入）、错题中（近似迁移）。

**内容质量提升空间**：● 高。**卡片字段 = 内容 Schema 强制约束**（五字段缺失则模板渲染残缺，质量问题显性化）；FSRS 数据（遗忘曲线/难度演化）是内容质量的反向审计素材（哪些卡片学完就忘 → 内容表述有问题 → 进 KM 复核）。配合 AnkiConnect 可编程化。

**内容适配综合分：8.0/10**（五段式 7、知识卡 9、错题 5.5、掌握度 9.5、每日计划 9、迁移 7.5、质量空间 9）

**KM-001 评语**：三个深入候选中**唯一"内容模型原生支持知识卡+掌握度+每日计划"三件套**的。对内容资产的增值点：五字段强制化、掌握度可观测化、质量反馈闭环化。短板在"练题判分"（主观自评非客观判分）和桌面端形态——但这两点恰好是现有 Flask 的强项，**互补关系而非替代关系**。

## 四、结论与推荐（知识管理视角）

### 4.1 核心结论

1. **内容资产的第一性问题不是"选哪个系统"，而是"内容模型还没强类型化"**。五段式解析目前是 `explanation` 单字段内嵌文本——**任何候选系统都"能装下"它，但没有任何候选系统会自动把它变成五字段**。哪个底座都改变不了这个事实，改变的只有我们自己的内容 Schema 与生产流程。
2. **三个深入候选的适配性排序（内容视角）：Anki+py-fsrs（8.0）> 面试鸭（5.5）> 学之思（4.5）**。学之思除错题本外对内容资产几乎无承载；面试鸭是"题目的好壳、知识卡的差壳"；Anki 是"知识卡+掌握度+每日计划"的原生容器，且 py-fsrs 是纯 Python 可嵌入现有 Flask。
3. **换底座必然伴随结构损失**：知识卡进面试鸭/学之思 = Markdown 四层结构退化为文本字段；掌握度进两者 = 12模块粒度退化为粗统计。**唯一"结构不损失甚至增值"的路线是 Anki 卡片字段化，或干脆不换底座、把内容模型在现有 Flask 上强类型化**。

### 4.2 KM-001 明确推荐（内容质量长期沉淀视角）

> **首选：方案 A（轻改造现有 Flask）+ 内容模型强类型化 + py-fsrs 增强组件**；若决策层坚持引入外部系统，**方案 C（Anki 作知识卡/掌握度/每日计划引擎，Flask 保留练题判分）次之**；面试鸭仅作刷题 UI 备选，学之思仅作错题本机制参考蓝本。

理由（纯内容质量角度）：
- **质量提升的前提是结构可校验**。在现有 Flask 上把五段式解析升级为**强类型五字段 JSON Schema**（`correct_answer/term_breakdown/option_analysis/exam_hint/mnemonic`，缺字段即校验失败），把知识卡规范化为 Markdown 四层结构 + 10 维度评分模板——这比迁移到任何系统都便宜且可控，且**直接消灭 mastery.json 脏数据类问题**（模块名枚举校验）。
- **py-fsrs 是唯一"零迁移、高增值"的组件**：pip 安装，直接对接现有 mastery.json（retention→mastery、difficulty→weak），把"粗粒度 0-100 估算"升级为"可预测遗忘曲线的科学排程"，每日计划（空目录）也一并解决。
- **Anki 路线对内容资产的增值在于"Schema 强制"**：五字段声明为卡片字段，模板渲染残缺=质量问题显性暴露，配合 FSRS 数据反向审计内容表述（学完就忘的卡 → 内容表述有问题 → 进 KM 复核队列）。这是其他候选都不具备的**质量闭环**。
- **不建议选面试鸭/学之思作底座**：两者对 11 张知识卡的承载都是"无处安放"，等于把已积累的结构化知识打回文本字段，长期看是内容资产的贬值；且两者掌握度模型空白，最终还是要回头接 py-fsrs。

### 4.3 建议的内容生产流程（与 KM-001 审核流程结合）

无论选 A 还是 C，内容生产统一走以下 7 步流水线（KM-001 审核嵌入第 4 步，不可跳过）：

```
① 采集      时政/公基素材（政府工作报告、一号文件、会议精神，标注来源）
② 初稿      TA-001 按模板产出：
            · 知识卡 → Markdown 四层结构（📌摘要/要点/表格/口诀/例题）
            · 题目   → 五字段 JSON（correct_answer/term_breakdown/
                       option_analysis/exam_hint/mnemonic）
③ Schema校验 五字段完整性 + 12模块名枚举校验（杜绝 mastery 脏数据复发）
④ KM-001审核 10维度评分（知识卡≥80、题目解析≥85 才放行；不合格打回带批注）
⑤ 入库      知识卡→知识库（Flask 目录 或 Anki 卡片字段）
            题目→题库 JSON / Anki 卡片（题干正面/五段解析背面）
⑥ 排程      py-fsrs 计算每日到期卡 → 生成每日计划（对接 daily-plan/ 与飞书推送）
⑦ 回流      答题/复习记录 → 错题本 + mastery 更新 → 薄弱模块触发 KM 补强
            （错题率高的题自动进入 KM-001 复核队列：题面歧义 or 解析误导？）
```

**关键落地动作（KM-001 建议，按优先级）**：
1. **本周内**：把 `explanation` 单字段拆为五字段 JSON Schema（15 题脚本一次性迁移，半小时工作量），mastery.json 模块名对齐 goal.yaml 12 模块枚举并清洗脏数据；
2. **本周内**：pip 引入 py-fsrs，mastery 计算迁移到 FSRS（历史数据作初始参数）；
3. **1 周内**：知识卡 11 张按 10 维度标准重制达标（当前平均 52.5 → 目标 ≥80，优先级：时政热点 3 张卡首轮返工）；
4. **决策点**：若走 Anki 路线（方案 C），知识卡按考点粒度拆分为复习卡的工作由 KM-001 定义拆分规则、TA-001 执行脚本，一次性完成即达质量门槛；
5. **长期**：错题高频题目 + FSRS 低保留率卡片 → 每月一次 KM 复核会，形成"内容质量反向审计"制度。
