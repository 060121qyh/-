## 1. 项目背景

### 1.1 旧系统概述

旧版"赛博导师·学案平台"（`~/hermes-study-mentor/`）是一个**单Agent系统**，包含6个Skill模块：

| Skill | 功能 | 状态 |
|-------|------|------|
| mentor-core | 学习导师核心逻辑 | 对话式教学 |
| goal-manager | 目标配置与管理 | 已运行 |
| intel-collector | 情报采集与飞书推送 | 每日3次Cron |
| quiz-simulator | 题库管理与练题 | 15题/批 |
| review-mastery | 掌握度追踪 | mastery.json |
| material-structurer | 知识卡结构化 | 12模块/13张卡 |

技术栈：Python 3.11+ HTTP Server（:8899）+ p5.js 中国风看板 + 飞书Bot推送 + GitHub Actions Cron

### 1.2 用户两次不满意的根因分析

| 次数 | 反馈 | 根因 | PM解读 |
|------|------|------|--------|
| 第1次 | "对话式教学不是他要的" | 系统定位偏差——旧系统以对话引导为主线，但用户要的是**结构化自学** | 交互模式错误：要图书馆，给了聊天机器人 |
| 第2次 | "单Agent没有分工协作" | 单Agent试图同时做内容生成、质量审核、功能迭代，没有制衡机制，质量不可控 | 架构缺陷：没有分离关注点，内容质量和代码质量都无人把关 |

### 1.3 用户明确需求

1. **多Agent协同架构**：PM-001（需求）→ TA-001（开发）→ QA-001（验收）+ KM-001（内容审核）
2. **结构化学习资料** > 对话式教学：知识卡为核心，不是聊天为核心
3. **练题 + 知识沉淀**：五段式解析、错题追踪、掌握度可视化
4. **中国风设计**：水墨卷轴、朱砂红、墨色谱（旧版已完成，需保留/增强）
5. **飞书推送 + Cron定时任务**：旧版基础设施保留复用

## 5. 系统架构设计（逻辑层）

### 5.1 多Agent协同模型

```
用户需求 ──→ PM-001（需求分析+任务分解）
                    │
                    ├── 任务JSON ──→ TA-001（编码实现）
                    │                    │
                    │                    ├── 代码产出 ──→ QA-001（质量审查）
                    │                    │                    │
                    │                    │              ┌─────┴─────┐
                    │                    │              │ 通过 → 完成 │
                    │                    │              │ 不通过 → 打回TA │
                    │                    │              └───────────┘
                    │                    │
                    │                    └── 内容产出 ──→ KM-001（内容审核）
                    │                                         │
                    │                                   ┌─────┴─────┐
                    │                                   │ ≥80 → 合格 │
                    │                                   │ <80 → 退回TA │
                    │                                   └───────────┘
                    │
                    └── 验收标准 ──→ QA-001（制定测试用例）
```

### 5.2 数据流设计

```
旧版数据目录                    新版系统
─────────────                  ─────────
goal.yaml      ──导入──→  目标管理API       ──→ 看板展示
knowledge-cards/ ──导入──→ 知识卡引擎 + KM审核 → 看板浏览
quiz-bank/     ──导入──→  题库引擎 + KM审核   → 练题交互
mastery.json   ──迁移──→  掌握度系统          → 进度追踪
daily-plan/    ──迁移──→  学习计划系统        → 每日计划
飞书Bot        ──保留──→  推送系统 + KM内容   → 飞书消息
```

### 5.3 技术约束

| 约束 | 要求 |
|------|------|
| 语言 | Python 3.11+ |
| Web框架 | Flask 或 FastAPI（TA-001在技术栈内选择） |
| 前端 | 原生HTML/CSS/JS + p5.js（中国风渲染） |
| 数据存储 | 文件系统（JSON/Markdown/YAML），不引入数据库 |
| 运行环境 | Windows 10, bash(git-bash), localhost |
| 部署方式 | 本地启动 `python server.py` |
| 消息推送 | 飞书开放平台 API |
| 定时任务 | GitHub Actions Cron (3次/日) |
