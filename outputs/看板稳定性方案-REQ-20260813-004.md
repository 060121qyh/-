## 一、问题根因回顾（已确诊）

| 症状 | 根因 |
|------|------|
| 用户多次反馈"一会就打不开了" | Flask 服务器是 Hermes 会话的**临时后台进程**，随会话结束/进程回收/电脑重启被杀 |
| 无任何兜底 | 没有开机自启、没有守护进程、没有公网通道 |

**结论**：本机 Flask 只是"看得见"的本地通道，真正根治需要三层方案叠加（本机常驻 + 公网静态镜像 + 手机端体验）。

## 二、问题 1：稳定性——本机 Flask 开机自启方案对比

### 方案 A：Windows 计划任务（schtasks onlogon）✅ 推荐

**做法**：`scripts/启动看板.bat`（cd 到项目根目录 → 用绝对路径 Python 313 启动 `server/app.py` → 写入日志）+
`schtasks /create /tn "学习导师看板" /tr "bat路径" /sc onlogon`

| 维度 | 评价 |
|------|------|
| 实现难度 | 低：1 个 bat + 1 条命令，无需额外依赖 |
| 权限 | 无需管理员（用户级任务，登录即启动） |
| 稳定性 | 进程在用户会话中运行，开机登录后自动拉起；配合 bat 内"端口占用检测"可防重复启动 |
| 维护 | 改 bat 即可；`schtasks /query` 可查状态 |
| 风险 | 电脑关机/不登录时无服务——**但此风险由公网版（问题2）兜底** |

### 方案 B：Windows 服务（NSSM / pywin32）❌ 本轮不选

| 维度 | 评价 |
|------|------|
| 优点 | 随系统启动（无需登录），崩溃可自动重启（NSSM 守护） |
| 缺点 | 需下载第三方工具 NSSM 或用 pywin32 编写服务代码；需要管理员权限安装；服务会话下无用户环境（网络驱动器/凭据问题）；配置成本显著高于计划任务 |
| 决策 | 本项目需求是"用户开机登录后本机可看"，计划任务已覆盖；**如后续需要"不登录也跑"，再升级 NSSM（预留演进路径）** |

### 方案 C：bat 放启动文件夹 ❌ 不选
与方案 A 等价但无法通过命令行查询/管理状态，且用户启动文件夹易被清理。不如 schtasks 可审计。

### 推荐：方案 A（计划任务 onlogon）
- 关键实现要点（写入 TA 任务）：
  1. bat 中**工作目录必须先 `cd /d` 到项目根目录**（Flask 靠相对路径读 config/data）
  2. Python 用**绝对路径** `C:\Users\乔一禾\AppData\Local\Programs\Python\Python313\python.exe`
  3. bat 先探测 `http://localhost:8899/api/health`，已活则退出（防重复实例）
  4. 日志重定向到 `scripts/看板启动日志.log`，便于排查
  5. `schtasks /create /sc onlogon /rl limited` 用户级任务，无需管理员

## 三、问题 2：公网——GitHub Pages 静态化方案评审

### 方案 A：GitHub Pages 静态化（数据静态化 + Actions 每日编译）✅ 推荐

**架构**：
```
GitHub Actions (每日定时 + 情报推送后触发 + 手动)
  ├─ knowledge-cards/*.md → 编译为 static-data/knowledge.json（前端同构的列表+详情结构）
  ├─ quiz-bank/*.json    → 合并编译为 static-data/quiz.json
  ├─ daily-intel（CI 内重新采集）→ static-data/intel.json
  ├─ platform.html       → 改造为「API 优先，API 不可达自动降级读静态 JSON」的双模版本
  └─ 推送到 gh-pages 分支 → 公网 https://060121qyh.github.io/-/
```

**可行性核验（本次评审已实地确认）**：
- ✅ 知识卡 `.md`（data/knowledge-cards/，9 个模块 11 张卡）已在仓库内、未被 .gitignore 排除 → Actions 可直接编译
- ✅ 题库 `.json`（data/quiz-bank/，49+ 题）在仓库内 → 直接合并编译
- ✅ 前端是纯静态 SPA（platform.html + p5/marked CDN 本地化），无服务端渲染依赖
- ✅ 情报数据 data/daily-intel/ 虽被 gitignore，但 `intel_collector.py` 在 CI 可重新采集 → 静态版情报每天同步
- ✅ 现有 daily-intel.yml 已具备 Actions 运行环境（Python 3.11 + pip 安装已验证）

**优势**：
1. **零服务器、零成本、零运维**——公网访问不依赖本机是否开机
2. 数据每天由 Actions 自动重编译，保证最新（知识卡/题库/当日情报）
3. GitHub 免费托管，全球 CDN，手机可直接打开
4. 静态站天然"打不开"概率极低（比本机 Flask 可靠一个数量级）

**风险与对策**：
| 风险 | 对策 |
|------|------|
| 🔴 **仓库是私有库**：GitHub Pages 免费档仅支持公开库（私有库需 Pro 付费） | TA 需先探测账号方案（`gh api user` 查 plan）；若免费档无法开 Pages，两条路：**① 将仓库转公开**（本项目内容为备考资料，无敏感密钥——secrets 在 Actions 层不随代码公开，.env 已被 gitignore，评估为可接受）；② 升级 Pro。**由用户决策，TA 产出操作说明** |
| 静态版无"错题本/掌握度"个性化数据（mastery/progress 是本机数据） | 定位为**查看型公网版**：知识宝库浏览、练题、看情报全部可用；个性化功能引导用本机版。前端做优雅降级提示 |
| 仓库名为 `-`，URL 为 https://060121qyh.github.io/-/ | Pages 路径前缀 `/-/` 必须贯穿：manifest/service-worker/静态 JSON 引用全部用相对路径，TA 需专门验证 |
| 部署不能破坏 daily-intel.yml | 新建独立 workflow 文件 deploy-pages.yml，**零改动** daily-intel.yml |

### 方案 B：云服务器部署 Flask（轻量云/ECS/宝塔）❌ 本轮不选
- 要买服务器/维护/备案，成本高周期长；数据本来就是静态可读的，杀鸡用牛刀。
- 若未来需要"公网+个性化"再评估（知识库数据需先上云）。

### 方案 C：Vercel / Cloudflare Pages 静态托管 ⚠️ 备选
- 技术上与 GitHub Pages 等价，但需额外账号绑定；GitHub Pages 与现有仓库/Actions 同生态，零迁移成本。**若私有库 Pages 卡住且用户不愿公开仓库，Vercel 是首选备胎**（私有库也免费）。

### 推荐：方案 A，若 Pages 开不通则回退 C 并同步用户决策。

## 四、问题 3：手机端——PWA vs 微信小程序

### 方案 A：PWA（manifest.json + service worker）✅ 推荐

**做法**：static/ 增加 `manifest.json`（名称/图标/主题色/display:standalone）+ `service-worker.js`（预缓存静态资源，离线可开），platform.html 注册 SW。

| 维度 | 评价 |
|------|------|
| 上线路径 | **零审核零备案零费用**——用户手机浏览器打开公网 URL → 添加到主屏幕 = 类 App 体验 |
| 开发成本 | 极低（两个文件 + 一行注册代码） |
| 双端复用 | 本机版（localhost:8899）与公网版（Pages）同一套文件同时获得 PWA 能力 |
| 离线能力 | SW 缓存后断网也能打开已缓存的页面/资源 |
| 局限 | iOS Safari"添加到主屏幕"体验略逊于安卓（iOS 16.4+ 已支持推送），但"随时查看"完全满足 |

### 方案 B：微信小程序 ❌ 暂不推荐（本轮明确否决）

| 门槛 | 说明 |
|------|------|
| 主体注册 | 个人主体可注册但**类目受限**，教育/备考类目个人主体多不可用 |
| 备案 | 小程序需要 ICP 备案（需服务器+域名，与问题2的免服务器路线矛盾，备案周期数周） |
| 审核 | 每次发版过微信审核，周期 1-7 天；**考试 8 天后（2026-08-22）就开考，时间窗口完全不允许** |
| 结论 | 备考场景时间紧、内容更新频繁（每日情报），小程序上线周期与需求节奏完全冲突 |

### 推荐：方案 A（PWA）。小程序留作考试后的长期演进项（若用户坚持要"真小程序"，考试后再启动主体注册流程）。
