## 三、推荐项目及理由

### 🥇 首选集成组件：py-fsrs（open-spaced-repetition/py-fsrs，468★，MIT）

**为什么是它**：
- **零迁移高增值**：纯 Python 库，`pip install fsrs` 直接嵌入现有 Flask；对接现有 mastery.json（retention→mastery、difficulty→weak 标记），把"粗粒度 0-100 估算"升级为 FSRS-6 科学排程（业界金标准算法，Anki 官方同款）。
- **一石三鸟**：同时解决两大用户痛点——**掌握度追踪**（可预测遗忘曲线）+ **每日计划**（到期卡自动排程，当前 daily-plan/ 目录是空的）。
- **硬标准对照**：星标 468（≥100 ✅）；release v6.3.2（2026-08-09）周更（✅）；issues 讨论活跃（✅）；MIT 许可无传染义务（✅）。
- **技术+内容双重印证**：TA-001 评"最轻量的增强组件"；KM-001 内容适配评分 **9.0/10 全场最高**（掌握度 9.5 / 迁移 9.5 / 质量空间 8）。

### 🥈 次选集成组件：surveyjs（surveyjs/survey-library，4,834★，MIT）

**为什么是它**：
- 前端问卷/测验**库**（React/Vue/Angular 皆可），quiz 模式支持正确答案、评分、判分反馈（可承载五段式解析渲染），中国风样式完全自控。
- 硬标准：4,834★、持续 release（2026-08-12）、497 open issues 极活跃、MIT。
- 定位：**练题渲染组件**，不承载内容资产（KM-001 内容适配 3.0 分，但这是组件口径——它本就该只干活不存内容）。

### 🥉 备选参考系统：Anki（ankitects/anki，29,680★，AGPL-3.0）+ fsrs4anki（4,039★，MIT）

**为什么值得参考/备用**：
- **知识卡+掌握度+每日计划三件套的原生容器**：卡片字段化（五段式五字段可声明为五个卡片字段，结构不损失）、FSRS 掌握度模型、每日到期卡自动排程。KM-001 内容适配 **8.0/10**（知识卡 9 / 掌握度 9.5 / 每日计划 9 / 质量空间 9——全场内容适配最高）。
- **质量闭环**：卡片模板渲染残缺=质量问题显性化；FSRS 数据反向审计内容表述（学完就忘的卡→进 KM 复核队列）。
- 硬标准：29,680★ 千星级、release 26.08.1 周更、338 issues/93 PR 极活跃（✅✅✅）。
- 注意：AGPL-3.0 许可（本地自用无碍，对外分发需开源自身）；桌面端形态，集成走 AnkiConnect 接口或直接借鉴 FSRS 算法（py-fsrs 即其算法库化）。

### 📖 参考蓝本：学之思 xzs（mindskip/xzs，3,891★，AGPL-3.0）

- **错题本机制是全部候选中最完整的**（答错自动收录+重练闭环，KM-001 错题项评分 8.5/10）——作为现有错题追踪的**机制参考蓝本**。
- 硬标准：星标✅ 维护✅（2026-08-12 周更）；社区互动⚠️ 在 Gitee 不在 GitHub——**该项部分满足**，按用户硬标准严格衡量应标注"部分达标"，故降级为参考而非底座。
- 不作底座原因：AGPL+Java 重栈、知识卡无落点（2.0/10）、五段式无结构（3.5/10）、掌握度无模型（3.5/10）。

## 四、集成方案（最终决策）

### 方案 A（✅ 首选执行）：轻改造现有 Flask + 组件集成——"不换底座"

```
┌─────────────────────────────────────────────────┐
│  现有 Flask 平台（localhost:8899，保留）          │
│  · 中国风 UI（水墨卷轴/朱砂红/墨色谱）—— 保留增强   │
│  · 飞书推送 + Cron —— 保留复用                    │
│  · 知识卡展示（Markdown 四层结构）—— 保留          │
├─────────────────────────────────────────────────┤
│  ➕ py-fsrs（pip 引入）                           │
│    → mastery.json 升级为 FSRS 掌握度模型          │
│    → 每日计划自动排程（对接 daily-plan/ + 飞书）   │
│  ➕ surveyjs（可选，练题渲染组件）                 │
│    → 即时判分 + 五段式解析渲染（中国风自控样式）    │
│  ➕ 内容模型强类型化（KM-001 关键动作）            │
│    → explanation 单字段 → 五字段 JSON Schema      │
│      （correct_answer/term_breakdown/            │
│        option_analysis/exam_hint/mnemonic）      │
│    → mastery.json 模块名对齐 goal.yaml 12 模块    │
│      （清洗 shizheng/URL编码/test 脏数据）        │
└─────────────────────────────────────────────────┘
```

**集成方式**：改造集成（非直接使用、非仅参考）——保留自建系统的内容资产与中国风体验，引入 py-fsrs 增强算法、surveyjs 增强练题交互、学之思错题本机制作参考。

**工作量预估**（TA-001/KM-001 共识）：
- 五字段 Schema 迁移：15 题脚本一次性迁移，约 0.5 天
- py-fsrs 接入 + mastery 迁移：约 1 天
- 知识卡 11 张按 10 维度重制至 ≥80 分：1 周内（时政热点 3 张优先）
- 每日计划排程 + 飞书推送对接：约 1 天

### 方案 C（次选备援）：Anki 混合路线

- Anki（+fsrs4anki）作**知识卡+掌握度+每日计划引擎**，Flask 保留**练题判分**；Flask 通过 AnkiConnect 接口读写。
- 触发条件：方案 A 落地后若用户对"知识卡复习体验/每日计划"仍不满意，升级走此路线。
- 注意：需用户安装 Anki 桌面端；知识卡需按考点粒度拆分为复习卡（KM-001 定义拆分规则，一次性完成即达质量门槛）。

### 明确不执行：换底座为面试鸭/学之思

- 两系统对 11 张知识卡的承载均为"无处安放"=已积累的结构化知识**打回文本字段**，长期是内容资产贬值。
- 掌握度模型两者皆空白，最终仍要回头接 py-fsrs——绕远路。

## 六、决策记录

**PM-001 最终决策**：
1. **执行方案 A**（轻改造现有 Flask + py-fsrs + 五字段强类型化），surveyjs 视前端改造进度作为练题组件引入；
2. **参考蓝本**：Anki（知识卡/SRS 架构）、学之思（错题本机制）——仅参考架构，不引入部署；
3. **备援**：方案 C（Anki 混合）在方案 A 落地后按需评估；
4. **并行内容动作**（KM-001 主张，已纳入）：五字段 Schema 迁移、mastery 脏数据清洗、11 张知识卡重制 ≥80 分；
5. **2026-08-22 考试保底**：任何底座动作不得中断内容生产；2 天无进展即回退。

**决策依据**：TA-001（技术可行性）+ KM-001（内容质量适配）**独立双重印证**同一结论；用户硬标准三项全部满足（星标≥100 ✅ / 维护记录 ✅ / 社区互动 ✅，学之思部分满足已降级处理）。
